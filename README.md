# 屋台注文システム

スマホ・タブレットなど複数の端末を使って、注文画面と厨房画面をリアルタイムに同期させる注文管理システムです。
注文画面で商品ボタンを押すとカードが追加され、注文画面・厨房画面どちらにも同じカードの列が表示されます。
カードはタップすると消え、注文画面では「取り消し」、厨房画面では「完成」として使えます。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | トップページ。注文画面・厨房画面へのリンクがあります |
| `order.html` | 注文画面。商品ボタンと、注文中の一覧(取り消し用)を表示します |
| `kitchen.html` | 厨房画面。注文中の一覧(完成用)を表示します |
| `count.html` | 「完成」ボタンが押された回数だけを表示するページ(取り消しはカウントしません) |
| `style.css` | 全ページ共通のデザイン |
| `common.js` | Firebaseとの通信・カード描画などの共通処理 |
| `firebase-config.js` | あなた専用のFirebase設定を書き込むファイル |

別々の端末どうしでカードをリアルタイムに同期させるには、どこかにデータを置いておく仕組みが必要ですが、GitHub Pagesはファイルを公開するだけの仕組みで、データを保存する機能がありません。そのため、このシステムでは無料のクラウドサービス「Firebase Realtime Database」にデータを置き、両方の画面がそこを見に行くことでリアルタイム同期を実現しています。

## セットアップ手順

### 1. Firebaseプロジェクトを作成する

1. [Firebase Console](https://console.firebase.google.com/) にGoogleアカウントでログインします。
2. 「プロジェクトを作成」をクリックし、プロジェクト名(例:`yatai-order-system`)を入力します。
3. Google Analyticsの設定を聞かれますが、このシステムには不要なのでオフのままで構いません。
4. プロジェクトが作成されたら完了です。

### 2. Realtime Databaseを作成する

1. 左側メニューから「Databases & Storage」→「Realtime Database」を開きます(メニューの場所が変わっている場合は、上部の検索窓で「Realtime Database」と検索してください)。
2. 「データベースを作成」をクリックします。
3. リージョン(地域)を選んで次へ進みます。どれを選んでも動作します。
4. セキュリティルールの初期モードを聞かれますが、どちらを選んでも次の手順4で上書きするので構いません。

### 3. Webアプリを登録して設定値を取得する

1. Firebaseコンソール左上の歯車アイコン→「プロジェクトの設定」を開きます。
2. 「全般」タブを下にスクロールし、「マイアプリ」欄の `</>`(ウェブ)アイコンをクリックします。
3. アプリのニックネームを入力し(例:`yatai-web`)、「Firebase Hosting」のチェックは不要なので付けずに「アプリを登録」をクリックします。
4. `firebaseConfig` という設定が表示されます。この中の7つの値(`apiKey`、`authDomain`、`databaseURL`、`projectId`、`storageBucket`、`messagingSenderId`、`appId`)を、このフォルダの `firebase-config.js` を開いて、対応する場所にそのままコピー&ペーストしてください。

### 4. セキュリティルールを設定する

Realtime Databaseの「ルール」タブを開き、内容を以下に書き換えて「公開」をクリックしてください。これにより、注文データ(`orders`)だけ誰でも読み書きでき、それ以外の場所は保護されます。

```json
{
  "rules": {
    ".read": false,
    ".write": false,
    "orders": {
      ".read": true,
      ".write": true
    },
    "completedCount": {
      ".read": true,
      ".write": true
    }
  }
}
```

※このシステムにはログイン機能がないため、URLとFirebaseの設定値を知っている人は誰でも注文データを読み書きできる状態になります。学園祭やお祭りなど短期間のイベント用としてはよくある割り切り方ですが、気になる場合はイベント終了後にFirebaseプロジェクトを削除するか、ルールを両方 `false` に戻してください。

### 5. GitHubで公開する

1. GitHubで新しいリポジトリを作成します(Publicにしてください)。
2. `index.html`、`order.html`、`kitchen.html`、`count.html`、`style.css`、`common.js`、そして手順3で書き換えた `firebase-config.js` を、すべてリポジトリのルート直下にアップロードします。
3. リポジトリの「Settings」→左メニューの「Pages」を開きます。
4. 「Build and deployment」の「Source」を「Deploy from a branch」にします。
5. 「Branch」を `main`、フォルダを `/(root)` にして「Save」をクリックします。
6. 数分待ってからページを再読み込みすると、公開URL(`https://ユーザー名.github.io/リポジトリ名/`)が表示されます。

### 6. 動作確認

1. 公開されたトップページのURLを、注文用の端末と厨房用の端末、両方のブラウザで開きます。
2. それぞれの端末で「注文画面へ」「厨房画面へ」をタップします。
3. 注文画面で商品ボタンを押すと、両方の画面にカードが追加されることを確認してください。
4. 注文画面でカードをタップすると取り消し、厨房画面でカードをタップすると完成として、そのカードが両方の画面から消えることを確認してください。

当日、毎回トップページを経由しなくて済むように、`order.html` と `kitchen.html` のURLをそれぞれの端末のホーム画面に追加(ブックマーク)しておくと便利です。

## カスタマイズ

- **商品の変更**:`common.js` の中の `PRODUCTS` の配列にある文字列を書き換えるだけで、商品ボタンの名前を変更できます。7種類以上に増やすこともできます。
- **色の変更**:`style.css` の先頭にある `:root` の中の色(`--order-accent` など)を書き換えると、全体の配色を変更できます。

## 注意点

- ES Modules という仕組み(`type="module"`)を使っているため、`order.html` などのファイルをパソコン上でダブルクリックして直接開いても動作しません。GitHub Pagesで公開したURL経由で開いてください(手元で試したい場合は、VS Codeの「Live Server」拡張機能などローカルサーバー経由なら動作します)。
- 通信エラーが起きた場合は、画面にエラーメッセージ(アラート)が表示されます。表示された場合はWiFi状況を確認してください。
- カードの並び順は、注文が追加された時刻(`time`)を基準にしているため、端末の時計が大きくずれていると順番が乱れる可能性があります。通常はスマホ・タブレットの自動時刻設定のままで問題ありません。
- `count.html` はトップページにリンクを置いていないため、URL(`.../count.html`)を直接開くかブックマークしてください。
- 完成数カウントをリセットしたい場合は、Firebaseコンソールの Realtime Database 画面で `completedCount` の値を直接 `0` に書き換えれば戻せます。
